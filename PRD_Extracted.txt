Version 1.0  |  Date: 01 November 2026  |  Status: Proposed / For Review
Reference inspiration: https://www.outskill.com/2-day-ai-mastermind
Document purpose: One consolidated specification for product owners, UI/UX designers, developers, QA, marketing and operations. AI Launchpad is a new, independent proposed brand; this document does not reproduce Outskill content or assert affiliation.
1. Executive Summary
AI Launchpad is a mobile-first website and workshop enrollment platform for practical beginner-friendly generative AI training. The first offering is a 2-day live bootcamp. Visitors discover the program, explore outcomes and curriculum, register, pay if applicable, and access a learner area. Administrators configure batches, instructors, content, enrollment, attendance and performance analytics.
Primary product goal: convert relevant visitors into confidently informed workshop registrants while ensuring dependable enrollment and an effective workshop experience.

3. Product Vision, Goals and Non-Goals
3.1 Vision
“Learn AI in 2 Days. Build Real Projects. Unlock New Opportunities.” Practical learning through demonstrations, guided exercises and real outputs.
3.2 Goals
Explain workshop value, who it is for, expected outputs and required prerequisites.
Drive high-quality registrations using accurate workshop details and clear calls to action.
Give learners a secure, usable post-registration experience.
Allow nontechnical administrators to update marketing and workshop operations.
Measure visits, lead-to-enrollment conversion, attendance and satisfaction.
3.3 Non-Goals for MVP
Native mobile apps and a full video-streaming platform.
Guarantees of employment, income, certification recognition or learning outcomes.
Marketplace of third-party trainers or complex subscriptions.
Personalized AI tutor and community feed.

8. End-to-End User Journeys
Visitor: ad/search/referral → landing page → curriculum/FAQ → select available batch → start registration → create account or verify email → payment if required → success/confirmation → learner dashboard.
Learner: sign in → see upcoming session in local timezone → access join link at approved time → attend → download resources → submit optional project → see completion status → receive certificate if eligible.
Admin: sign in with privileged role → create draft workshop and batch → configure capacity and price → publish → track enrollments → support users → record attendance → manage refunds/completions → export reports.
9. Registration and Enrollment Specification
9.1 Registration Form
Fields: full name, email, phone with country code, user category, selected batch; optional experience level; mandatory Terms/Privacy acknowledgement and separate optional marketing consent.
Front-end and server-side validation; accessible inline errors and clear help text.
Email normalization, anti-bot/rate limits, duplicate handling and clear conflict resolution.
Enrollment ID generated once; confirmation page and email include program, date, timezone, receipt (if paid) and support contact.
9.2 Seat and State Rules
Workshop states: draft, published, unpublished, canceled, completed. Batch states: scheduled, full, closed, in-progress, completed, canceled. Enrollment states: pending, payment_pending, confirmed, canceled, refunded, attended, completed. Actual availability must derive from server data, not static UI.
Concurrent enrollments must use transactional seat-capacity enforcement. For paid cohorts, a temporary reservation and expiry policy should be defined. Payment webhook retries must be idempotent.
10. Payments, Pricing and Refunds
Free and paid workshop modes; configurable currency, tax, coupon, start/end time and batch-level price.
Display subtotal, tax, discount and total before confirming checkout.
Create payment orders securely on server; never trust client-reported success.
Verify provider signatures/webhooks, store external transaction references, and reconcile mismatches.
Handle success, pending, failure, retry, cancellation, refunds and chargeback states.
Send receipt and payment confirmation; keep payment data minimal and never store full card numbers.
Refund policy must state eligibility, turnaround and contacting support; legal owner to approve.

12. Instructor and Admin Portal
Role model: Learner, Instructor, Support, Admin, Super Admin. Least privilege by default. Instructor access is limited to assigned workshops; support should not have unrestricted payment or administrator privileges.
Manage landing page content, FAQs, mentors, testimonials and workshop metadata.
Create cohorts with date, timezone, duration, capacity, joining instructions and enrollment cutoffs.
Review/search/filter registration lists and export authorized datasets.
Send manual/automated transactional notifications and correct schedule changes.
Record attendance and issue/revoke certificates with audit logs.
View payments, refunds and aggregate operational metrics without exposing card details.
Manage users, role assignments, policies and admin actions with auditable history.
13. UX / UI and Content Standards
Visual direction: contemporary AI education brand with dark navy, blue/violet accents, high-contrast text, restrained gradients, airy spacing, consistent icons and focused action buttons. The final design must be distinct from reference competitors.
Mobile-first for narrow screens; desktop and tablet responsive behavior.
Visible form labels and focus states; WCAG 2.2 AA target.
Day 1/Day 2 tabs keyboard operable; no hidden essential content.
Real examples and truthful claims; avoid fabricated logos, numbers, profiles or testimonials.
Consistent empty/loading/success/error states for every data-driven section.
Use local timezone labels and explicit date formats; avoid ambiguous “tomorrow” in static copy.
Optimize hero media, lazy-load below-fold assets, respect reduced-motion settings.

15. System Architecture and Integrations
Suggested stack: Next.js + TypeScript + Tailwind CSS for the website; server-side Next.js endpoints or NestJS for business logic; PostgreSQL for transactional data; a managed auth provider; S3-compatible storage; email delivery provider; Razorpay or Stripe for supported payments; managed cloud hosting; analytics and monitoring.
Logical components: public content layer; identity/access layer; workshop/catalog service; registration/capacity service; payment/webhook service; notifications; learner portal; admin console; reporting/analytics; data storage.
Integration dependencies: video conferencing provider, calendar invitation generation, transactional email/SMS optional, payment gateway, analytics and optional CRM. Use environment secrets, webhook verification, least-privileged credentials and staging integrations.

19. QA Plan and Acceptance Criteria
A visitor can view full, accurate program details at common viewport widths.
Day tabs, FAQ, anchor links, keyboard navigation and forms operate accessibly.
Registration succeeds for an open batch and returns a unique record.
Duplicate submissions cannot create duplicate active enrollments or payments.
Last-seat concurrency cannot oversell a batch.
Past/full/closed/canceled batches cannot be enrolled in.
Payment success is accepted only after server-side verification and idempotent processing.
Email and calendar details agree with stored schedule and timezone.
Learners cannot read or change another learner’s account or materials.
Instructor and admin permissions are enforced server-side.
Cancellation, failure, refund, expired reservation and webhook retry paths are tested.
Admin can publish, update and unpublish batches with audit trail.
Certificate generation follows defined attendance/completion rules.
Usability, accessibility, performance, backup recovery and security tests are documented.
